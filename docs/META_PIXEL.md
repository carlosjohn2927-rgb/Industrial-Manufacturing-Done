# Meta Pixel and Conversions API

## Setup

1. In **Dashboard → Website settings → Meta Pixel**, enter the numeric Pixel ID, select the events and enable the integration. It is off by default. The settings permission is required. No database migration is needed.
2. Optionally paste a Conversions API token in the write-only field. A token entered here is encrypted in the settings table with the application's encryption key; it is excluded from the shared settings cache and the raw settings editor. Keep `VP_ENCRYPTION_KEY` stable and protect database backups and server access. Alternatively set `VP_META_CAPI_TOKEN` in the server environment/.env; the saved token takes precedence. Clearing the saved token falls back to the environment token, so remove that too to disable CAPI. PHP OpenSSL and cURL are required. Token and encryption key are never sent to the browser.
3. Review the consent language and privacy policy with your privacy adviser before enabling. The visitor can accept or reject advertising tracking and reopen Tracking preferences, even after the integration is disabled if a preference was already saved. The choice lasts six months; withdrawal reloads the page and attempts to remove the first-party `_fbp` and `_fbc` cookies. Browser or third-party cookie policies can affect removal. No Meta script or CAPI event is sent before consent. If a conversion occurred before consent it is not sent retroactively.

**Important privacy limitation:** Meta's browser script may collect the current page URL, including the RFQ thank-you URL containing a quote reference, and possibly other page data. To avoid leaking arbitrary query or fragment data, the Pixel is suppressed on authentication/reset routes, URLs with fragments, and URLs with query strings except a single validated opaque `fbclid` parameter. This preserves attribution for a standalone Meta click ID while PageView and ViewContent are missed on other query-bearing pages, including campaigns with additional parameters. Review URLs and Meta's collection practices before enabling; avoid including sensitive data in URLs. The browser Pixel is a third-party script controlled by Meta. CAPI sends only the source route without query strings, client IP, user agent and, when present, the first-party `_fbp` / `_fbc` identifiers, and never sends form contents or customer contact fields.

## Events and limitations

* `PageView`: once per public layout page after consent, excluding auth/reset pages, fragments and query strings other than a standalone validated `fbclid`.
* `ViewContent`: product detail page, with database product ID, name, category and USD starting price where available. A catalog listing does not imply that every listed item has been viewed. Prices are starting prices, not completed sales.
* `Search`: non-empty product/site search form submission on a page where the Pixel is active; no search term is sent. Autocomplete requests do not fire it. Direct search URLs and searches initiated from disallowed query-bearing pages are not tracked. Navigation can interrupt browser delivery.
* `Contact`: after a contact is saved; `Lead`: after an RFQ is saved (an RFQ is treated as a lead, not a separately sales-qualified lead). Both optionally send CAPI and queue one matching browser event with the same `event_id` for Meta deduplication. The browser event is queued in the visitor session for its matching success destination for up to 30 minutes; unrelated requests cannot consume it. Refreshing or directly visiting a thank-you page does not create a conversion. Withdrawal or global disable clears pending events. If the visitor closes the browser, the server copy may be the only one sent.
* There is no shopping cart, checkout, payment processor or order/purchase model in this repository. The AddToCart, InitiateCheckout, AddPaymentInfo and Purchase switches are reserved; **none fires**. Do not interpret RFQs as purchases. These require integration with a future real commerce flow and verified payment success, including real order data and idempotency.

CAPI uses a synchronous, best-effort HTTPS call with a three-second timeout and no retry queue. Errors are logged generically without the token or response body. The dashboard reports configuration, not live Meta connectivity. Event delivery can be blocked by browser extensions, connectivity, the server firewall, or a Meta API/token error. Verify Graph API version support periodically. Cookies and the session queue mean browser/server deduplication is best effort; if either channel is blocked only the available channel is received.

## Verification on a staging domain

1. Configure a test Pixel and token; set the server-only `VP_META_TEST_EVENT_CODE` to the `TEST...` code from Events Manager so CAPI events appear in its Test Events view. Remove it after testing. Ensure outbound HTTPS to `graph.facebook.com` and browser access to `connect.facebook.net`/Meta endpoints. Check browser network traffic before opting in: no Meta script, requests or CAPI conversions. Reject and verify again, then accept and verify one Pixel load and one PageView. Withdraw, reload, and verify no further events.
2. With Meta Pixel Helper and **Events Manager → Test events**, visit a product and submit a search from a clean URL once. Confirm the expected events and product fields. Toggle each event off and confirm it stops; refresh and inspect for duplicates. Do not use sensitive search text or production customer data for the test.
3. With consent, submit a valid contact and RFQ and confirm one Contact and one Lead in Test Events. Compare the browser `eventID` to the server `event_id` and confirm Meta reports deduplication. Refresh/directly visit thanks and submit invalid forms: no new conversion should be created. Check PHP logs for generic CAPI delivery errors. Disabling the integration should suppress both channels.
4. Do not verify Purchase until a real payment/order flow exists. Repeat these checks on mobile and with blockers; seek legal review of the consent implementation for each target jurisdiction.

## Local checks

`node tests/meta_pixel_browser_check.js` exercises browser gating and queuing with a mock DOM. `php tests/meta_pixel_check.php` tests the library and rendered partial with fake dependencies and a fake CAPI transport. They do not contact Meta or substitute for the staging checks above.
